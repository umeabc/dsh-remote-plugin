# 适配 DSH 0.2.2-rc.1（2026-11-06）

桌面端从 `0.2.1-rc.5` 升到 **`0.2.2-rc.1`**（asar 182MB → 213MB，`hostProtocolVersion` 仍是 4）。
这次新增了 24 个包（action-cards、context-menu、file-actions、message-quotes、forge、liveshare、
official-bundles…），前端 bundle 整体换了哈希。

## 宿主 API：仍然没变

| 插件用的 | 0.2.2-rc.1 |
|---|---|
| `ctx.webServer.register({kind, path, handler})` / `getOrigin()` | 同签名（`dsh-host-webserver/lib/index.js:375`、`:363`）；另外新增了 Fetch `resource` 形式的路由，旧的 handler 形式继续支持 |
| `ctx.connection.admit({headers})` / `authenticatedUrl()` | 同签名（API catalog 里仍在 `connection` 服务下） |
| `ctx.get('tools').register({...})` | 同签名，`mobile_access` 正常 |
| `__ModuleLoader__.load({id, factory})` + `slots.register('settings.section')` | 同契约 |
| `data-dshm-boot` / `--dshm-safe-bottom` | 页面照常写入，安卓端无需改 |

所以还是在**界面结构**上出问题，这次是四处。

## 1. 会话被挤成三分之一宽（最明显）

390px 下打开任何会话，正文只剩 223px，左边空出 160px。

根因：0.2.2 的 frame 从「两列」变成带具名区域的**三列**，并且每个子元素被显式钉到网格线上：

```html
<div class="…_frame" style="grid-template-columns: 0px minmax(0px,1fr) minmax(0px,0px)">
  <div class="…_sidebarCol">   <!-- position: fixed，脱离流 -->
  <div class="…_centerCol" style="grid-column: 2">
  <div class="…_rightbarCol" style="grid-column: 3">
  <div class="…_bottomRow" style="grid-column: 1 / -1">
```

我们的 `grid-template-columns: minmax(0,1fr) !important` 只塌掉了模板，`centerCol` 仍然声明要第 2 条线，
于是浏览器补出一条隐式轨道，把内容挤进 230px。

改法（`assets/mobile.css`）：塌模板的同时把 `centerCol` 也放到第 1 条线，`bottomRow` 保持跨满。

```css
html[data-dshm-mobile='1'] [data-dshm-frame] { grid-template-columns: minmax(0,1fr) !important; }
html[data-dshm-mobile='1'] [data-dshm-frame] > [class*='centerCol'] { grid-column: 1 !important; }
html[data-dshm-mobile='1'] [data-dshm-frame] > [class*='bottomRow'] { grid-column: 1 / -1 !important; }
```

实测：`cols: 390px`、`center: [0, 390]`、无横向溢出。

## 2. 设置弹窗反而被我们改坏了（0.2.2 自己会做手机布局了）

0.2.2 给设置弹窗加了窄屏媒体查询：

```
.AnXs9G_panel{grid-template:"title header""nav nav""options options" minmax(0,1fr)/minmax(0,1fr) auto; width:100%; height:100%}
```

也就是标题+关闭、横向标签页、内容。而我们的 `[data-dshm-settings-panel]{display:flex;flex-direction:column}`
是给 0.2.1 的 800px 网格打补丁用的，套到新网格上会让 `navTitle` 变成被拉伸的 flex 项（实测 415px 高），
标题贴在顶上、标签页被推到屏幕外，中间一大片空白。

改法（`assets/mobile.js`）：只在弹窗**仍然是桌面尺寸**时才打标记，否则把标记摘掉、交给 DSH 自己。

```js
if (panel.getBoundingClientRect().width >= window.innerWidth - 8) {
  panel.removeAttribute('data-dshm-settings-panel');
  ...
  return;
}
```

这样 0.2.2+ 用原生窄屏布局，0.2.1 及更早仍然吃我们的兼容层。实测标题、标签页、内容都正常，
`.dshmb-root` 358px 宽、无横向溢出。

## 3. 会话头被两个新按钮挤没

0.2.2 在会话头加了「…更多操作」「用文件资源管理器打开」和一颗「N 个后台任务运行中」。
390px 下标题只剩 43px（显示成「适…」），而且文件夹按钮在手机上本来就没意义（它打开的是**电脑上**的资源管理器）。

改法：手机隐藏「文件资源管理器」和「后台任务」两颗按钮（任务状态在输入框上方的折叠条里已经有了），
标题回到 195px；「…」保留。选择器用 `aria-label`，不依赖 CSS module 哈希。

## 4. 运行统计换了个位置

0.2.1 里那行统计在 `[data-slot="conversation.composer.dock"]`；0.2.2 把它挪进了
`[data-slot="conversation.composer.bar"]` 里的 `GRgSLq_dock`。旧规则因此失效，手机上又冒出
「6 轮 357 步·169 tok/s 58M tok·缓存命中…」和底部「24%」。

改法：两条选择器都写上。

## 5. 顺带：zstd

`decompress()` 只认 gzip / deflate / br。Chrome 123+ 会在 `Accept-Encoding` 里带 `zstd`，
而 DSH 的 web server 现在支持按请求压缩；一旦上游回 zstd，注入就会静默失败 —— 手机拿到的是桌面壳。
补上 `zstdDecompressSync`（Node 24 自带），并在 `test/lan-e2e.mjs` 加了一条：假上游回 zstd 页面，
桥必须解压后再注入。改前 FAIL（`encoding=zstd`、注入缺失），改后 PASS。

## 关于「所有项目」

- `dsh-mobile-relay`：与 DSH 版本无关（它只转帧），`relay-e2e` 全绿，线上实例 `connected: true`。
- `dsh-mobile-android`：代码零改动（只依赖 `data-dshm-boot`、`--dshm-safe-bottom`、`dshm://` 和内容哈希
  资源回放）；内置壳资源已用 `tools/sync-web-assets.mjs` 同步到 0.2.2-rc.1 的前端（88 个文件 / 5.1MB）。
- `dsh-mobile-bridge`、`dsh-remote-pc`：都被 `dsh-remote-plugin` 取代且不在任何 profile 里，标记为归档，不再适配。
