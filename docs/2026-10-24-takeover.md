# 0.2.0：远端接管整个窗口

## 之前

「设置 → 远程电脑」连上之后只有一颗「打开远端界面」，点它 `window.open(…)` 会**另开一个浏览器窗口**
（`http://127.0.0.1:8331/`）。感觉像“又开了一个 DSH”，而且那个浏览器窗口和 DSH 桌面本身没有任何关系。

## 现在

连上之后**整个 DSH 窗口切成远端**：

- 顶部 40px 工具栏：`● 远端模式 · relay.example.com:9443`（左，单行省略）+「退出视图」+「断开连接」（右）。
- 下面整块是远端 DSH：`<iframe src="http://127.0.0.1:8331/">`，内容由加密隧道代理到远端桌面的 loopback web server。
- 无 CSP 限制：DSH 的 index 既没有 `Content-Security-Policy` 头也没有对应 meta，所以跨端口 iframe 不被拦。

断开有三条路：

| 位置 | 行为 |
|---|---|
| 工具栏「断开连接」 | 收起界面 + `POST /__pc/disconnect`：停隧道、停 8331 监听、清掉保存的连接码 |
| 「设置 → 远程电脑」的「断开连接」 | 同上 |
| 工具栏「退出视图」 | 只收起界面，连接保留；回设置页可再「接管整个窗口」 |

连接成功后自动接管（不再需要点第二下），刷新页面也会回到远端：

- 接管状态记在 `localStorage['dsh-remote-plugin:takeover']`；
- 页面加载时若这个键还在、且 `/__pc/status` 说已连接，就重新挂上 iframe；
- 连接断了（`connected: false`）会自动收起，不会把人困在死 iframe 上；
- 只在顶层窗口挂载（`window.top === window.self`），避免 iframe 里再套一层。

## 宿主侧

`GET /__pc/status` 现在多一个 `host` 字段（`relay.example.com:9443`），工具栏用它显示远端地址。
新增 `POST /__pc/disconnect`：

```js
store.data.clientLink = '';
await client?.proxy?.stop();
await client?.tunnel?.stop();
client = null;
await store.save();
```

`GET /__pc/status` / `POST /__pc/link` / `POST /__pc/disconnect` 都要桌面浏览器登录态（`ctx.connection.admit`）。

## 验证

- 预览架子（`preview/`）新增「已连接」模拟：点「接管整个窗口」→ 工具栏出现、iframe 里是占位页；
  点「断开连接」→ 覆盖层消失、卡片回到输入态（截图 06–08）。
- 真机：`/__pc/disconnect` 由 404 变 401（路由已注册），版本号 0.2.0，
  设置页文案与提示已是新版（截图 09）。
- 还没在**两台真机**之间跑过端到端：需要你在 B 机上再试一次，看 iframe 里远端界面是否完整、输入法/快捷键是否正常。

## 已知限制

- iframe 里是远端 UI，浏览器级快捷键（Ctrl+L 之类）归宿主窗口；应用内快捷键在 iframe 获得焦点后正常。
- 断开后再连需要重新粘贴 `dshm://` 连接码（本机保存的那份已清掉）。
- 如果远端把 `X-Frame-Options: DENY` 加回来，iframe 会被浏览器拦掉；届时改成整窗跳转
  （`location.href = 8331`）也只需要改这一个函数。
