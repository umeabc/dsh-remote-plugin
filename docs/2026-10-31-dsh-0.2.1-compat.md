# 适配 DSH 0.2.1-rc.5（2026-10-31）

桌面端从 `0.2.1-rc.3` 升到 **`0.2.1-rc.5`**（`desktop-runtime.json`：`hostProtocolVersion: 4`），
插件上一轮实测停在 rc.3，这次按「宿主 API → 客户端 API → 手机界面 → 接管」四层重新对了一遍。

## 怎么核对的

- **API 层**：从 `D:/dsh/resources/app.asar` 解出整个 `dsh/`（453MB，2026-10-31 的 rc.5 构建），
  直接读 `dsh-host-webserver`、`dsh-client-ui-settings*`、`dsh-client-hmr` 的实现和 CSS。
- **行为层**：本机 8320 的局域网通路 + 390×844 / DPR2 / 触摸 的 Edge（Playwright）走一遍：
  配对 → 首页 → 抽屉 → 会话 → 设置 → 手机访问 → 远程电脑 → 接管。
- 全程零 `pageerror`、零 console error，说明模块加载与 slots 注册这层没有断。

## 结论一：宿主和客户端的 API 都没变，不用改

| 插件用的 | 0.2.1-rc.5 里 |
|---|---|
| `ctx.webServer.register({kind, path, handler})` | 同签名，重复注册抛错（`dsh-host-webserver/lib/index.js:326`） |
| `ctx.webServer.getOrigin()` | 同签名（`:314`） |
| `ctx.connection.admit({headers})` / `authenticatedUrl()` | 同签名，路由鉴权照常 401/200 |
| `ctx.get('tools').register({...})` | 同签名，`mobile_access` 工具正常出现在工具表里 |
| `window.__ModuleLoader__.load({id, factory})` | 同契约；`id` 必须等于包名，否则 `loaded without registering` |
| `ctx.slots.register({name,id,order,label}, Component)` | 同签名（`dsh-client-ui-settings-general/lib/client.js:1151`） |

所以没有「换 API」的改动，问题全在**界面行为和资源占用**上。

## 结论二：四个真问题

### 1. 连接成功后不自动接管（还会在握手时被自己踢掉）

复现：设置 → 远程电脑 → 粘贴 `dshm://` 链接 → 保存并连接。卡片变「已连接」，但窗口没有切到远端；
手动点「接管整个窗口」又正常。

抓到的时序（在页面里包一层 `fetch` + `Storage.setItem` + `MutationObserver`）：

```
setItem  dsh-remote-plugin:takeover = http://127.0.0.1:8331/   ← save() 里的 enterTakeover
overlay-added
link-response  url=http://127.0.0.1:8331/  connected=false      ← 隧道还在握手
removeItem dsh-remote-plugin:takeover                          ← 被 effect 收掉
overlay-removed
```

根因在 `client.js` 的退出条件：

```js
if (!connected && readTakeoverUrl() !== '') leaveTakeover();
```

`POST /__pc/link` 的响应里 `connected` 一定是 `false`（`ClientTunnel` 的握手还没回来），
而 4 秒一次的 `/__pc/status` 轮询也可能先落到 `connected: false`。于是「刚挂上又被判定成断线」。

改法：

- 退出条件换成**连接码还在不在**（`status.link !== ''`），而不是 `connected`；
  再补一个 `known`（拿到过响应），否则首帧 `status === null` 会被当成「没有连接码」。
- `save()` 里先 `writeTakeoverUrl()` 记住意图，等 effect 看到 `connected === true` 再挂 iframe。

### 2. 长连接把上游 socket 池吃干，整个 bridge 卡死（本次最严重）

现象：连着打开十几次手机页面之后，`GET /` 通过 bridge 直接不返回（curl 25s 无响应），
而 `/__mobile/status`（不走上游）仍然毫秒级返回 —— 典型的连接池饥饿。重启 DSH 才好。

根因两处叠加：

- DSH 的客户端 HMR 是 **SSE**：`/plugins/events` 每个打开的页面都长期占一条连接
  （`dsh-client-hmr/lib/index.js:143`，`content-type: text/event-stream`）。
- `Upstream` 的 keep-alive agent 写死 `maxSockets: 32`，于是第 33 个请求起全部排队；
  又因为 `forward()` 没有处理「手机那头已经走了」，关掉的页面不会释放上游请求，队列只增不减。

改法（`core.js`）：

```js
this.agent = new Agent({ keepAlive: true, maxSockets: Infinity, maxFreeSockets: 64 });
...
response.on('close', () => { if (!response.writableEnded) upstream.destroy(); });
```

回归测试 `test/pool-e2e.mjs`：开 40 条 SSE，然后打一个普通请求；关掉全部 SSE，看上游是否全部释放。

```
改前：  PASS  普通请求（空载）
        FAIL  40 条长连接到达上游 - open=32 rejected=8
        FAIL  长连接满时普通请求仍可服务 - timed out after 4s
        FAIL  关页面释放上游 socket - closed=0/32
改后：  4/4 checks passed（普通请求 3ms，40/40 释放）
```

### 3. 手机上多了一条运行统计

0.2.1 在输入框下面固定了一条 `[data-slot="conversation.composer.dock"]`：轮数/步数、tok·s、
缓存命中、上下文占用。桌面上是诊断信息，手机上它把输入框顶高、自身还被裁成「1 轮 136 步 · 1…」。
按 README 一直写的「手机隐藏 token/速度统计」，用 slot 名隐藏（slot 名比 CSS module 类名稳定）：

```css
html[data-dshm-mobile='1'] [data-slot='conversation.composer.dock'] { display: none !important; }
```

### 4. 悬浮按钮压住会话头的「… 更多操作」

0.2.1 的会话头右上角新增了「…」和「在文件管理器打开」。实测（390px）：
悬浮按钮 `340..378`，`更多操作` 按钮 `342..370` —— 完全重叠，菜单点不到。

DSH 的头部是 `grid`，`padding: 10px 28px 0 20px`；`headerCorner` 还有个 `margin-right:-16px`，
所以那排按钮距右边只有 12px。给头部右侧多留一条：

```css
html[data-dshm-mobile='1'] [data-slot='conversation.header'] header { padding-right: 64px !important; }
```

## 还需要重启后复核的

宿主半侧（`index.js` / `core.js`）改动**必须重启 DSH** 才生效；`client.js`、`assets/` 是 bridge
现读现发，刷新手机页面就生效。

- 第 2 条（连接池）只有重启后才落到运行中的进程上：重启后再连续开关 20 次手机页面，
  `curl -H "Cookie: dshmb=…" http://<ip>:8320/` 应当仍然是毫秒级。
- 第 4 条的 64px 是按 DSH 的 CSS 算出来的（悬浮按钮右缘 12px + 38px 宽 + 4px 余量），
  重启后用真机/390px 视口量一次 `更多操作` 的 `getBoundingClientRect().right` 应 ≤ 336。
- 明暗两套主题下再看一眼设置页与抽屉（本轮冻在亮色；token 用法没动过，风险低）。
